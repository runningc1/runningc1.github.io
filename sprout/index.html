Tuesday, October 27, 2026 2026-10-27

One-click export of a process map with everything attached to it Live

A request from a recorded conversation: give the ID of one process map and get the map and all of its related records as one nested JSON document, ready to paste into a planning model. The page copies the whole document at once, or one table at a time, or downloads any table as a spreadsheet file.

  • The export follows a fixed list of relations instead of every link in the database, so it never wanders into unrelated large tables, and it reads everything in a fixed number of queries however big the map is.
  • Testing on the largest real map found three problems before release: rich-text notes that ran as templates when read, related records that store their name under a different field, and records that ran extra queries every time they loaded. All three were fixed and covered by tests.
  • Shipped behind the same access rule as the map page itself, after staging and browser checks. A day of real use showed no errors.

Monday, October 26, 2026 2026-10-26

Follow-up checks and close-out on four fixes from last week Live

Each fix stays open until it has run through real working days and the logs and data show it holds. Tonight four passed and were closed:

  • A page address that sent the browser into an endless redirect loop now opens the right page, and a new guard shows a not-found page instead of looping when any redirect points back at itself.
  • Starting the time clock from a task link no longer crashes; a bad link now gets a clear error.
  • Each production day now gets its shift on the day itself through a scheduled job, instead of the next morning, so same-day schedule views show break times.
  • Removed an outdated test that failed on every run and hid real test results.

Monday, October 19, 2026 2026-10-19

Cut automated test runs to about a quarter of their time Live

The test suite now runs in parallel worker processes instead of one. Measuring first showed that one large smoke test took most of the run on its own, and a single test cannot be spread across workers, so I split it into smaller test classes that cover the same pages.

  • Running in parallel exposed two hidden dependencies between tests: a cache shared across test processes, and state left over from an earlier test. I fixed both at the source instead of working around them.
  • Checked with repeated parallel and single-process runs before merging; every test passes.

Friday, October 16, 2026 2026-10-16

Found why some shop-floor station pages are slow Analysis

Some station pages took much longer to open than others. Request logs showed server capacity was not the cause; profiling one page open found an N+1 query pattern. I estimated the operator waiting time it costs and wrote a fix plan: tests that pin the current output and query counts first, then the query fixes, then a staging check and a before-and-after measurement on the floor.

Fixed a nightly sync job that was failing without reporting it In review

A nightly job that keeps stock levels in step with the online store had stopped completing, and its error handling hid the failure. The fix records the real error and makes the job fail visibly so monitoring catches it, with tests. Its first run waits on a business decision.

Made the test suite pass again In review

The ERP's test suite would not run. I made it runnable and fixed the tests that had fallen behind code changes, so the whole suite passes. Test-only changes; no application code touched.
